数据体检

给台账做一致性检查 —— 输入几个 CSV，输出一份能直接发给同事看的问题报告。

它解决什么问题

手工维护的台账，错的地方往往不是「算错了」，而是「没对上」：发票挂的合同号写错了、同一个单号录了两遍、 流水金额和发票差了一万、某个金额多打了一个零。

这些错误单看每一行都正常，只有交叉比对才能发现。这个工具把交叉比对写成规则，一次跑完。

核心是一张关系图

规则只是关系的可执行版本。整个模型只有一条主干：

合同 ─┬─ 开票 ── 收款流水
          └─ 分包 ── 成本归集
                    └→ 项目毛利

合同是唯一源头，所有钱都从它长出来。其中「产值 × 约定收款比例 = 应收」这一层最关键 —— 它把「钱该什么时候到」从记忆变成了可计算的数字，欠款才可能被自动发现。

穿透：任何数字都能追到源头

判断关系模型设计得完不完整，有个很硬的标准：能不能从任何一个数字追到它的源头和归属。

python checkup.py --trace HT-2026-005

输出产值 → 应收 → 每张发票 → 每笔到账 → 分包 → 成本归集 → 毛利。 示例数据里这一屏同时暴露三个问题：发票号重复导致串单、某笔付款多了一个量级、项目毛利因此显示为负 183 万。

怎么用

  • 纯 Python 标准库，不需要安装任何依赖
  • python checkup.py 检查自带示例
  • python checkup.py 我的数据目录 检查自己的数据
  • python checkup.py --trace 单号 穿透查看一个单号的完整链条
  • 终端输出摘要，同时生成单文件 HTML 报告

十条规则

  • 必填项缺失、单号重复、疑似重复记账
  • 引用不存在、时间倒置、日期格式不统一
  • 金额为负、超额开票、金额不符、应收未收、疑似离群值

离群值用四分位距判断而非平均数 —— 一笔极端值会把平均数拉高，反而藏住它自己。
