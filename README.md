# 数据体检 · data-checkup

给台账做一致性检查的命令行工具。输入几个 CSV，输出一份能直接发给同事看的问题报告。

> 它不修改你的数据，只指出哪里对不上。

## 解决什么问题

手工维护的台账，错的地方往往不是"算错了"，而是**没对上**：发票挂的合同号写错了、同一个单号录了两遍、
流水金额和发票差了一万、某个金额多打了一个零。这些错误单看每一行都正常，只有交叉比对才能发现。

这个工具把交叉比对写成规则，一次跑完。

## 跑起来

不需要安装任何依赖，Python 3.8+ 自带的标准库就够。

```bash
python checkup.py                  # 检查自带示例数据
python checkup.py 我的数据目录       # 检查自己的数据
python checkup.py 目录 --open      # 跑完自动打开报告
```

示例数据里故意埋了 13 个问题，用来演示每一条规则。跑完会在终端打印摘要，同时生成 `checkup-report.html`。

## 输入格式

数据目录里放三个 CSV（缺哪个就跳过依赖它的检查，不会报错）：

| 文件 | 用途 | 字段 |
|---|---|---|
| `contracts.csv` | 合同台账 | `contract_no` 合同号、`customer` 客户、`sign_date` 签订日期、`amount` 金额、`type` 类型 |
| `invoices.csv` | 开票台账 | `invoice_no` 发票号、`contract_no` 关联合同、`issue_date` 开票日期、`amount` 金额、`tax_rate` 税率 |
| `ledger.csv` | 收支流水 | `id`、`date` 日期、`category` 分类、`direction` 收支方向（`in`/`out`）、`amount` 金额、`ref_no` 关联单号 |

日期统一用 `YYYY-MM-DD`，金额是纯数字（不要带单位）。

## 九条规则

| 规则 | 级别 | 在找什么 |
|---|---|---|
| 必填项缺失 | 严重 | 分类、金额这类字段为空。空值不会报错，只会让统计静默失真 |
| 单号重复 | 严重 | 同一个发票号出现两次，金额会被算两遍 |
| 疑似重复记账 | 警告 | 日期、分类、方向、金额四项全同，大概率是录重了 |
| 引用不存在 | 严重/警告 | 发票挂的合同号、流水挂的单号在主表里找不到 |
| 时间倒置 | 严重 | 开票日期早于合同签订日期 |
| 日期格式不统一 | 提示 | 混用 `2026/5/20` 和 `2026-05-20`，按月汇总会漏 |
| 金额为负 / 为零 | 严重/警告 | 负数是冲销还是符号录错？零金额是否有业务意义？ |
| 超额开票 | 严重 | 同一合同的开票合计超过合同金额 |
| 金额不符 | 警告 | 流水金额与对应发票金额不等 |
| 疑似离群值 | 警告 | 金额比同类大一个量级 |

## 两个刻意的设计选择

**离群值不用平均数判断。**
一笔 260 万的记录会把平均数拉高，结果反而"藏"住了它自己。这里用四分位距（IQR）：取中间 50% 数据的分布范围，
超出 `Q3 + 3×IQR` 才算异常。极端值再怎么大，也不会污染自己的判断基准。

**规则可插拔，一条规则一个函数。**
`checks.py` 里每条规则都是「输入全部数据 → 输出问题清单」，互不依赖。要加一条新规则，
写一个函数扔进 `RULES` 列表即可，不用动读取、报告、命令行任何一处。

## 输出

- 终端：按严重程度排序的问题清单，带定位（第几行、哪个单号）和修复建议
- `checkup-report.html`：单文件报告，不引用外部 CSS/JS/字体，拷走就能打开，也能直接打印

## 目录

```
data-checkup/
├── checkup.py      命令行入口：读数据、跑规则、输出
├── checks.py       九条规则 + 问题数据结构
├── report.py       HTML 报告渲染
└── sample/         虚构示例数据（埋了 13 个问题）
```

示例数据里的公司名、金额、单号全部虚构，与任何真实企业无关。
